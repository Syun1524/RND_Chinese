ROBOTICS;NOTES DaSH Steam 版简体中文补丁 v1.5

**v1.4 及更早版本的用户直接覆盖安装即可。** 安装器会把 v1.4 留下的两个多余图片文件清掉。

## 相对 v1.4 的变化

### 手柄操作图不汉化

系统菜单 → 帮助页里，**手柄模式**的按键说明一直是日文原图（`跳过 / 向后翻页`、
`自动模式`…），而**键盘模式**同一页却正常显示中文。

根因不在图片，也不在重定向表 —— 那两处一直是对的。问题在运行时的一个判断：
帮助页的手柄图与键盘图分别是 `manual` 归档的 **fileId 0** 和 **fileId 1**，
而 CoZ 上游的 `mgsFileOpenHook` 用 `fileId > 0` 判断「这次确实要打开一个文件」，
于是 **fileId 0 被整条跳过**。键盘图（1）正常，手柄图（0）永远是原版。

判据是像素级的：拿日文原图集的一行标签当模板，在用户截图上做归一化互相关 ——
日文模板 **1.0**，中文模板 **0.185**。画面上就是日文原图。

改法：源码里 `fileId > 0` → `fileId >= 0`。`-1` 是引擎唯一的哨兵值（表示「改用文件名」），
所以只多放行 0 这一个真实下标；没配 key `"0"` 的归档照样原样落下。

### 补丁包里的重复图片

`control_pc.png` 与 `RND_PC_controller_jp.png` 内容完全相同（键盘那对同理），
因为日文原版 `system.cpk` 与 `manual.cpk` 里这两张图本来就各存了一份。
CoZ 上游让两个归档**指向同一份**，我们这边因为去重是按「归档里的原始文件名」比对的、
而两个归档里名字不同，所以一直留着两份。

这不只是多占空间：`sync_images.py` 的同步源只映射到其中一份，另一份**没有源文件**
—— 现在两份内容恰好相同看不出问题，一改图，`system/33` 那条路径就会静默停在旧图上。
v1.5 把它们合并成一份（`cls` 79 → 77 行，13 处下标同步重排），两个归档现在指向同一条目，
文件名用 `control_pc.png` / `keyboard_pc.png`。

### 其他

- 版本号升到 1.5（安装器 / 启动器界面、包名、文档）。
- 安装器升级时清理 v1.4 遗留的那两个重复文件（复制步骤只覆盖/新增，不会自动清旧条目）。
- 仓库侧新增两道门禁：`check_shared_guides.py`（共享图集必须只存一份、两个归档必须指向同一下标）
  与 `check_fileid0_guard.py`（fileId 0 必须被放行），各配负向自测。
- 构建链补全：`contrib/include/nlohmann/` 收进单头 `json.hpp`（vcpkg 的该端口在本机装不上），
  仓库现在可以独立重编 LanguageBarrier。

## 安装

下载 `RNDZh-Setup-v1.5.exe`（约 233 MB），双击安装。
Steam 版与免 DVD 版通用；补丁会自动处理含特殊字符的安装路径。
