# 服装核对指南

> 目的：把 **11 个多变体角色的 61 套服装**逐一认出来（哪套是水着、哪套是体操服、哪套是私服……）。
> 单变体角色（c007/c009/c010/c011/c013/c014/c015/c016 共 8 个）没有别的服装可切，不列入。
>
> CoZ 泳装那 10 套已确认（见下表），剩 **51 套**待认。

## 一、为什么需要核对

游戏把每个角色的每套服装存成一个独立的 `.lkm` 模型（`c002_100.lkm` 这种），
但**文件里不含任何服装名称**。已逐项排除过的可能来源：

| 可能的来源 | 结论 |
|---|---|
| `.lkm` 模型二进制 | 只有网格 + 内嵌贴图，无名称串 |
| `.scx` 脚本 | 压缩格式，全文无 `c0NN_MMM` 形式引用，不引用变体名 |
| `.lka` 动作文件 | 只有动画名（`stand`/`walk_loop`），无服装名 |
| 游戏文本（msb/enscript） | 只有通用词汇（水着/体操服/ブルマ/メイド/猫耳/浴衣） |
| 系统菜单文本 | **游戏根本没有换装菜单**（这正是 CoZ 要用 fileIdRemap 硬改的原因） |
| CoZ 原版补丁 | `swimsuitPatch` 只点名了 10 个泳装模型，无描述 |
| 邻接补丁 glossary | 只有泛化术语，无按模型映射 |
| `.lkm` 内嵌贴图 | **可解出来看** —— 这是唯一可行的离线线索 |

所以：**离线看贴图认，剩下拿不准的进游戏实地看。**

## 四、路线 B：进游戏确认（拿不准的用这个）

工具是独立 exe：`RNDZhOutfitTool.exe`（**不随补丁发布**，只给开发者用）。
已放在两个游戏根目录各一份：

- `D:\Ruanjian\Steam\steamapps\common\ROBOTICS;NOTES DaSH\`
- `D:\ZZGAME\ROBOTICS NOTES DaSH\`

**步骤**

1. 运行游戏根目录的 `RNDZhOutfitTool.exe`
   （**不需要**先在启动器里开「泳装／换装模式」—— 见下方原理）
2. 界面显示「第 N / 61 套 · cXXX_YYY · cXXX 全部服装都会变成这一套」
3. 点「开始游戏」→ 进游戏看这个角色穿的是什么
4. 退出游戏 → 回工具 → 点「下一套 ▶」→ 再进游戏

**每次只需两次点击。** 角色/服装两个下拉框可直接跳到指定项，`◀`/`▶` 顺序遍历全部 61 套。
核对顺序按角色分组：c001 四套 → c002 十套 → c003 八套 → ……

**注意**：核对是「把该角色的**全部**变体都指向选中的那一套」，所以你看到的是
"这个角色穿了这一套"。角色在哪出现取决于剧情 —— 找个该角色出镜的场景看。

### 原理（备查）

- 选择写进 `%LOCALAPPDATA%\Committee of Zero\RNDSteam\config.json` 的
  `zzOutfitOverride`（`"c001_070"` 形式，关闭时是 `"off"`）。**别手改**，工具会写。
- 对应 `patchdef.json → settings.zzOutfitOverride.choices[<id>]`，
  内含该角色**全部变体 → 目标变体**的 `fileIdRemap`。目标自身也映射到自己，
  否则会被 `swimsuitPatch` 覆盖回泳装（`json_merge` 是递归覆盖，删不掉键）。
- `zzOutfitOverride` 按键名字典序排在 `swimsuitPatch` 之后，所以核对胜出。
  **不要重命名这个键**，改成排在 `swimsuitPatch` 前面的名字会静默失效。
- 只影响被核对的角色。开着泳装模式时其它角色是泳装；关着时其它角色是原版默认服。
- **核对不依赖「泳装／换装模式」。** `mgsFileOpenHook` 读 `config["patch"]["fileIdRemap"]`
  是**无条件**的，且命中后直接 `return`（不会落到 `fileRedirection`）。所以：
  - 泳装模式**开** → 被核对角色穿选中的那套，其它角色穿泳装
  - 泳装模式**关** → 被核对角色穿选中的那套，其它角色穿原版默认服

  两种都能核对，关着时画面干扰更少（推荐）。
- 两个程序的配置互不干扰：启动器保存时会**原样保留未知键**，
  所以它不会把工具写的 `zzOutfitOverride` 抹掉。

## 七、已知事实（不要再重复查证）

- **19 个角色 / 69 套变体**；多变体角色 11 个，共 61 套需核对，其中 10 套已确认。
- 69 套**两两内容都不同**（已做全量 md5 对比），没有可合并的。
- `.lkm` **内嵌贴图**：`<uint32 大小>"DDS "` 记录，2048×2048 DXT1/DXT5，可直接解出。
- 贴图**槽位顺序在不同变体间会错位**（c004_070 把脸部贴图排在最前，c004_010 排最后），
  所以一律按**内容哈希**匹配，不能按索引。
- 每个变体的服装贴图通常只有 **3~10 张**，其余十几张是全变体共用的脸/眼睛/身体。
- motion 文件名泄漏角色名：`c003_070_frau@rnd_dance_5.lka` →
  c002=akiho、c003=frau、c004=junna、c007=kou、c013=kou、c018=daru。
  这些是**变体号 + 角色名**，但给不出服装名。
