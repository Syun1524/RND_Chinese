# 片头覆盖字幕变更记录

记录 2026-09-28 为 **片头 `mv_rnd_prologue`** 添加简体中文覆盖字幕所做的改动。

游戏目录：`D:\Ruanjian\Steam\steamapps\common\ROBOTICS;NOTES DaSH`
字幕目录：`languagebarrier/subs/`

---

## 1. 背景：为什么是「覆盖」而不是重编码

片头在画面上**烧死了英文引文与标题**（原版素材自带，擦不掉）。补丁的做法是
在原画之上叠一层中文 `.ass`，**完全不碰 `movie.cpk`**（省掉 1.75 GB 重编码）。

机制与 5 首歌曲的字幕相同：`patchdef.json` 的 `base.fmv.subs` 按**影片 id**
映射到 `.ass` 文件名，走 `mgsMovieCPlayerPlayByIdHook`
（本作 `videoPlayerVariant: rnd`）。

片头的影片 id 是 **51**（`mv_rnd_prologue.usm`）。日文版 / 英文版 / Steam 正本
三个 `movie.cpk` 里都是 51（只有 44/45/48/49 在英文版带 `_en` 后缀，51 不带）。

与歌曲字幕的区别：走 `base.fmv.subs` 而**不是** `settings.karaokeSubs` ——
引文与标题是剧情内容，不该受「影片字幕」开关影响。

## 3. 排版：中文夹住原画英文

原画英文是两行（小字 + 主标题），中文各放其一侧，形成「中-英-英-中」对称块：

| 行 | 字号 | 与上下行间隙 |
|---|---|---|
| `科学ADV系列`（中） | 48 | — |
| `SCIENCE ADVENTURE SERIES`（原画） | — | 25px |
| `ROBOTICS;NOTES DaSH`（原画） | — | 24px |
| `机器人笔记 DaSH`（中） | 74 | 25px |

引文段：三行居中，行距 66px；署名紧跟引文块下方、右缘对齐中文块右缘
（原画署名即紧贴引文，不是沉在画面角落）。

### ★ 原画整段有「推近运镜」，这是对齐的最大干扰

逐帧实测：引文段英文行距随时间**从 93px 收到 65px**，署名右缘也从 x1904 漂到 x1642。
**中文是静止层，无法与动态的英文逐帧对齐**，只能取某一帧为基准。
本次取用户截图那一帧（t≈6.0，英文 66px）。

**教训：拿静态截图判断动态画面时，先问「这是第几秒」**，否则基准点就错了。

## 4. 淡入淡出：普通 alpha 渐变，用 `\fad` 复刻

渲染器是 **xy-VSFilter**（不是 libass），支持 `\fad` / `\t(\alpha)` / `\t(\clip)`。

### ★ 判「统一 alpha」还是「擦除」的判据

最初看到字母「零散出现」，差点写成「逐字擦除」——**那是误判**。决定性判据是
测「该处背景亮度」与「文字可见度」的关系：

| 位置 | 背景亮度 | 文字可见度 |
|---|---|---|
| x=1002（天线剪影上） | 24.5（暗） | 219.5（已显） |
| x=1122（地球云层上） | 132.6（亮） | −12.5（看不见） |

**同一 alpha 下暗底先显、亮底后显 → 统一 alpha 渐变**，「零散」只是背景明暗不均的错觉。

### ★ 测淡出不能用「偏白像素计数」

该判据在 alpha≈0.5 时就归零，**把淡出后半段整段漏掉**（第一版据此把主标题淡出
写成 1.45s，实际是 2.0s）。正确判据：文字蒙版内像素的
「相对无字基准帧的增量」求和 = 与 alpha 线性对应的能量，取 5%/95% 分位点。

### 实测时间线

| 段 | 淡入 | 淡出 | `\fad` |
|---|---|---|---|
| 引文 | 0.93→2.5 | 6.03→6.4 | `fad(1500,400)` |
| 署名 | 1.03→2.4 | 6.5→7.1 | `fad(1300,600)` |
| 上行小字 | 20.25→20.60 | 24.55→26.05 | `fad(350,1500)` |
| 下行主标题 | 20.55→21.30 | 25.55→27.55 | `fad(750,2000)` |

**两行是「重叠」淡出，不是先后接替** —— 上行 24.55 起降时下行仍满亮，
下行从 25.55 才开始降。别按「第一阶段/第二阶段」去设。

## 5. 字体

| 字体 | 家族名 | 来源 | 用在哪 |
|---|---|---|---|
| `RNDSerifSC-Regular.ttf` | `RND Serif SC` | 思源宋体 SC 静态实例（wght 500） | 引文、署名（原文是衬线） |
| `RNDTitleSC-Light.ttf` | `RND Title SC` | 思源黑体 SC 静态实例（wght 300） | 标题卡（原文是细体无衬线） |

用 `instantiateVariableFont` 取静态实例并**改家族名**——Windows 已注册同名的
**变量字体**，不改名会让 GDI 匹配到不确定的那份（同 `make_lyric_font.py` 的理由）。

两者**必须**放进 `languagebarrier/subs/fonts/` 并列入 `patchdef.json` 的
`base.fmv.fonts`，否则 VSFilter 找不到。

## 6. 产物

| 文件 | 用途 |
|---|---|
| `subs/mv_rnd_prologue.ass` | 游戏内（PlayRes 1920×1088，与游戏渲染面一致） |
| `subs/tools/build_prologue_subs.py` | 生成器（单一数据源 → 游戏版 / PR版 / srt） |
| `subs/tools/verify_prologue_subs.py` | 验收（差分法测落点与安全边距） |

生成器同时产出 PR 用的 1920×1080 版与 `.srt`（PR 不解析 ASS 的 `\pos`/`\fad`）。
**PlayRes 必须分两份**：游戏渲染面高 1088、视频高 1080，直接用游戏版进剪辑会偏 8px、
底部元素被裁。

## 7. 验收

```bash
python subs/tools/verify_prologue_subs.py
```

判据：渲染「带字幕帧」与「不带字幕帧」相减，只留字幕像素再测位置 ——
每段都必须完整落在画面内（距底 > 20px）。实测两个 PlayRes 版本 `ALL PASS`。

⚠️ 不要用「最底亮像素」判裁切：背景的白色云层会被误当成字幕
（曾据此误报「字幕被裁」）。
