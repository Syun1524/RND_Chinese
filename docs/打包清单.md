# 打包清单（自研安装包用）

> 目的：把"补丁包体"和"安装器程序"分开。**本文件只管包体（数据/文档）**，安装器程序见 `docs/安装器设计.md`。
> 前提：不使用 CoZ 官方安装器（`nguninstall.exe` / `ngreceipt.bin`），也不参考隔壁方案。
> 基准：工作区 `RND补丁英文成品原版/` 是 CoZ 英文补丁的成品包，可作**文件结构**参照（仅结构，不含内容）。
>
> **包体已搭好**：`9.6文本外工作/成品ing/补丁包/`（482 文件 / 465.5 MB）
> 清单：`成品ing/补丁包_文件清单.txt`、`成品ing/补丁包_manifest.json`（含 dinput8.dll md5）
> 测试安装：`成品ing/_手动安装_测试用.bat`（放在包体外，避免混入交付内容）

## 0. 两条铁律（2026-09-11 新增）

1. **c0data 条目的文件名 = 游戏原始资源名**（取自各归档 `解包日志.txt`），
   **不使用 CoZ 自己加的 `_en` 等后缀**（游戏自带的 `_last`/`_jp` 保留）。
   附带 `c0data.cls` 与 `fileRedirection` 的同步重建，见 `scripts/rebuild_c0data.py`。
2. **外观必须是本补丁自己的**：不用 CoZ 的图形化启动器/图标/品牌，见 `docs/启动器设计.md`。

## 4. 配置项（发布前必须定）

### 4.1 `versioninfo.json`
当前 `updateCheckUrl` 已从 CoZ 改为本仓库：
```
https://raw.githubusercontent.com/Syun1524/RND_Chinese/main/update.json
```
**未发布 `update.json` 时启动器只会提示"检查失败"**（无害），不会再指向 CoZ 英文补丁。
发布后往仓库 `main` 放 `update.json` 即可启用更新提示。

### 4.2 `defaultconfig.json`（用户默认配置）
`rawConfig = merge(defaultconfig, 用户配置)`，所以**改这里 = 改所有玩家的初始状态**。
- 要**默认开启泳装模式** → 加 `"swimsuitPatch": true`
- `fontPath` 建议与 `patchdef.base.fontPath` 一致（现在都指向 `NotoSansCJKsc-Regular.otf`）

### 4.3 `appdatadir`（✅ 已在包内修复）
`patchdef.json` 的 `appdatadir` 决定用户配置落在哪个目录：
```
路径 = %LOCALAPPDATA%\<appdatadir>\config.json
```
- CoZ 原值：`Committee of Zero\RNDSteam`（启动器 `LauncherC0.exe` 正是写这里）
- 实机曾是空串 `""` → 配置落到 `%LOCALAPPDATA%\config.json`，与启动器写的目录**不是同一个**
  → 后果：**启动器里所有开关（泳装/鼠标/卡拉OK…）对 CN 补丁无效**（这正是泳装开不起来的根因）
- **已修复**：包内 `languagebarrier/patchdef.json` 的 `appdatadir` 已设为 `Committee of Zero\RNDSteam`，
  与随包启动器一致，开关立即生效。

> 注：`fontPath` **只从 `patchdef.base` 读**（`TextRendering.cpp:69`），
> `defaultconfig.json` 里的 `fontPath` 是**误导死配置**，包内已删除。

### 4.4 `patchName` / `patchVersion`
现为 `ROBOTICS;NOTES DaSH Chinese Patch` / `0.1`，建议改成正式名与版本号。

## 5. 字体缓存：不要预置

- `font_*.dds` / `outline_*.dds` / `fontData.bin` 是**运行时按当前码表烘焙**的产物（约 414 MB）。
- 不预置的理由：包体 +414 MB；且缓存带 `charsetHash` 指纹，**玩家侧码表/字体一旦不同就整份作废重烤**，预置收益不稳定。
- 代价：首启要烘焙（多进界面逐步烤全字号），**正是崩溃高发窗口**——已通过字体兜底（`missingGlyph`）降低风险。
- 若日后确定要预置：必须**保证玩家侧码表与字体与烘焙时逐字节一致**（自包含安装包可做到），并接受包体 +414 MB。

## 6. 泳装 / 换装模式

- 实现方式：`patchdef.json` 的 `settings.swimsuitPatch.setters.fileRedirection.model`，把 48 个 `model` fileId 重定向到 c0data 的 10 个 `.lkm`。
- 对应文件：`c0data/` 下 `c001_070.lkm` … `c019_020.lkm`（共 10 个，248 MB）——**必须进包**，否则开启后换装模型加载失败。
- 开关：用户配置的 `swimsuitPatch`（见 §4.2 / §4.3）。当前实机已设为 `true` 供测试。

## 10. 体积与压缩（2026-09-11 实测）

| 部分 | 原始 | deflate 后 | 压缩率 |
|---|---|---|---|
| `c0data/*.png`（83 张） | 137.6 MB | 137.2 MB | **100%**（PNG 已压缩，无收益） |
| `c0data/*.lkm`（10 个泳装模型） | 247.8 MB | **57.5 MB** | **23%** ← 最大收益 |
| `enscript/*.msb`（322） | 2.7 MB | 1.3 MB | 46% |
| `subs/`（含字体） | 52.4 MB | 34.0 MB | 65% |
| `fonts/*.otf` | 16.4 MB | 13.6 MB | 83% |
| `NOTES DaSH/*`（DXVK 等） | 17.8 MB | 6.5 MB | 37% |
| 根目录 dll | 18.0 MB | 7.8 MB | 43% |
| **整包** | **496 MB** | **≈ 260 MB** | **52%** |
| 整包（不含泳装模型） | 248 MB | ≈ 202 MB | 81% |

**结论**：
1. **应当以压缩形式发布**（zip 或安装器内压缩载荷），465 MB → **约 260 MB**。
2. **泳装模型占原始体积 50%，压缩后仅占 22%**。建议把它拆成**可选组件**：
   - 基础包（不含泳装）：约 202 MB（压缩后）
   - 泳装组件：约 58 MB（压缩后）
   - 玩家按需下载，基础包体积腰斩。
