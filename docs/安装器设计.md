# 安装器设计（待实现）

> 包体已就绪：`成品ing/补丁包/`（482 个文件，465.5 MB，见 `成品ing/补丁包_文件清单.txt`）。
> **本文件只描述安装器程序该做什么**，不含 CoZ 官方安装器、也不参考隔壁方案。
> 临时测试可直接用包内 `_手动安装_测试用.bat`（逻辑与下面的流程一致）。

---

## 1. 要解决的事

把 `补丁包/` 的整棵树写进游戏根目录，且做到：能定位游戏、能校验版本、能备份、能卸载、且**不会因为旧缓存/旧版本把游戏搞坏**。

---

## 2. 流程

```
① 定位游戏目录
     ├ 注册表: HKCU\Software\Valve\Steam\SteamPath / HKLM ...\Steam
     ├ 解析 <Steam>\steamapps\libraryfolders.vdf 得到所有库盘
     ├ 在候选路径下找 steamapps\common\ROBOTICS;NOTES DaSH\Game.exe
     └ 找不到 / 找到多个 → 弹目录选择框（用户选含 Game.exe 的文件夹）
   校验: 同级必须有 script.cpk、system.cpk（否则不是正确目录）

② 确认游戏已关闭
     tasklist 查 Game.exe / launcher.exe，运行中则提示先退出

③ 版本校验（硬门禁）
     对 Game.exe、script.cpk、system.cpk 取哈希，与「支持的版本表」比对
     ├ 匹配   → 继续
     ├ 不匹配 → 停止并提示（游戏更新后 SigScan 特征码可能失效，不能硬装）
     └ 该表随补丁发布，新增游戏版本需实测后补

④ 备份
     记录本次将要覆盖的既有文件（存在才备），拷到 <游戏>\_cn_patch_backup_<时间戳>\
     另外记录一份「本次写入了哪些文件」的清单，供卸载用

⑤ 清除旧字体缓存
     删 languagebarrier/fonts/ 下的 font_*.dds、outline_*.dds、fontData.bin
     （码表/字体变了旧缓存会错位 → 显示错字，必须清）

⑥ 写入包体
     按 补丁包/ 目录树整份覆盖写入游戏根目录
     （含 NOTES DaSH\dinput8.dll —— 注意在子目录！）

⑦ 写卸载信息
     登记自己的卸载项（显示名/版本/卸载命令），**不要沿用 CoZ 的
     nguninstall.exe / ngreceipt.bin 注册项**

⑧ 完成提示
     说明：首启会烘焙字形；请正常退出游戏
```

---

## 3. 卸载

用 ④ 记录的清单：删除本次写入的文件 → 从备份恢复被覆盖的原文件 → 恢复原版启动器/根目录文件。
**不删**玩家自己生成的字体缓存（可选：一并清理以免残留）。

---

## 4. 边界情况

| 情况 | 处理 |
|---|---|
| 游戏目录选错（无 Game.exe/无 cpk） | 拒绝，重新选择 |
| 找到多个游戏副本 | 让用户选，不猜 |
| 游戏正在运行 | 拒绝安装 |
| 已装过旧版补丁 | 直接用备份恢复原版后再装新版（或允许覆盖并保留旧备份） |
| 磁盘空间不足 | 安装前检查（包体 + 备份，约需 1 GB 余量） |
| 游戏本体版本不匹配 | 停止（③），提示等待补丁跟进 |
| 玩家手动删过 languagebarrier | 全量写入即可，无需特殊处理 |

## 10. 【已实现】单文件安装包（2026-09-11）

**成品**：`setup/RNDZh-Setup-v0.1.exe` — **188 MB**（原始 459 MB，压缩率 41%）

### 做法：7z SFX

```
7z.sfx  +  sfx_config.txt  +  payload.7z   →   拼接成一个 exe
```

玩家双击 → SFX 自解压到临时目录 → 自动运行 `RNDZhSetup.exe`（GUI 安装器）。

构建：`python setup/build_installer.py`（约 25 秒）

> **为什么用 Python 而不是 .bat 构建**：补丁包路径与 SFX 配置都含中文，
> cmd 的代码页（GBK/65001）处理这些会错乱，Python 处理 UTF-8 无此问题。

### 安装器 `RNDZhSetup.cpp`（原生 Win32 + GDI+，无外部依赖）

界面与启动器同一套配色/字体/图标。流程：

1. **自动定位游戏目录**（本程序目录 → 上级目录 → 注册表 Steam 路径 → 各盘
   `Steam/SteamLibrary\steamapps\common\ROBOTICS;NOTES DaSH`），失败则「浏览…」
2. **校验**：目录须含 `Game.exe` + `script.cpk`
3. **识别语言**：读 `boot.bat` 的 `JP`/`EN`（决定存档目录），界面显示"日文版/英文版"
4. **备份**：被覆盖的文件 → `<游戏目录>\_cn_patch_backup_<时间戳>\`，
   并保留一份 `_cn_patch_boot_orig.bat`
5. **清字体缓存**：`fonts/font_*.dds`、`outline_*.dds`、`fontData.bin`
6. **复制**：包内全部文件 → 游戏根目录（带进度条）
7. **写回 `boot.bat`**：`start RNDZhLauncher.exe <JP|EN>` —— 让 Steam 的「开始游戏」
   也进补丁启动器（Steam 的启动配置 `executable` 就是 `boot.bat`）。语言保持原样。

> ⚠ 第 7 步**不是**靠 `patchdef.json` 的 `hijackLauncher` 实现的（那条路在这个游戏上
> 不生效：MAGES 的 `launcher.exe` 不导入 DINPUT8，代理 DLL 进不去）。
> 详见 `docs/启动器设计.md` §2。

失败时弹出具体原因（游戏在运行 / 文件被占用 / 无写权限）。

### 实测验证

- SFX 解包 470 个文件（补丁 469 + 安装器自身），**与原包逐字节比对：0 差异**
- 目录层级、中文文件名均正常
- 归档可被 7z 正常识别（`7z l RNDZh-Setup-v0.1.exe`）

### 体积构成

|---|---|---|
| 泳装模型（10 个 `.lkm`） | 248 MB | **约 37 MB**（15%）|
| 其余（图集/译文/字体/DLL） | 211 MB | 约 151 MB |
| **合计** | **459 MB** | **188 MB** |

## 12. 【已实现】同归档自引用重定向（省 248 MB，2026-09-11）

### 动机（用户提出）

泳装模式的 10 个 `.lkm` 模型原本被**复制进 `c0data/`**（248 MB）。
但实测发现：**游戏自己的 `model.cpk` 里就有这些文件**——
`c0data` 那 10 个与游戏自带的**逐字节完全相同**（CoZ 只是把它们拷了一份）。

于是可以**不复制文件，改为"同归档内改 fileId"**。

### 实现：新增 `fileIdRemap`

在 `patchdef.json` 增加与 `fileRedirection` 并列的新机制：

```json
"fileIdRemap": { "model": { "466": 469, "467": 469, ... } }
```

含义：**请求 `model` 归档的 fileId 466 → 改读同归档的 fileId 469**。
不换归档、不复制文件，`mgsFileOpenHook` 里保持 `vfsObject` 不变、只改 `pThis->fileId`。

`Game.cpp` 中新增约 20 行，置于 `fileRedirection` 之前（有 remap 就优先走 remap，
否则回落到原有的 c0data 重定向，两者共存、互不影响）。

### 为什么可靠

| 检查项 | 结果 |
|---|---|
| 游戏自带 `model.cpk` 的 fileId 是否稳定 | **四个版本（Steam/3DM/日版副本/英版副本）`model.cpk` md5 完全相同**（`51b1cbc15b`）→ fileId 稳定 |
| 目标文件是否真的在游戏里 | 10 个 `.lkm` 在 `model` 归档中的 fileId：469/474/485/496/502/509/512/518/524/531 |
| 新机制是否生效 | ✅ 实测：`mgsFileOpen(system, 0x16) remapped in system to 0x7` |
| 是否影响原有图片重定向 | ✅ 实测：`redirected to c0data` 仍正常（9 次/标题画面） |

### 效果

| | 改造前 | 改造后 |
|---|---|---|
| 补丁包 | 459 MB | **220 MB** |
| 单文件安装包（7z） | 188 MB | **151 MB** |
| `c0data` 文件数 | 98 | 88 |

**附带好处**：不再分发游戏素材（那 10 个模型是游戏自带的），分发合规性更好。

### 索引迁移注意

从 `c0data/` 移除 10 个 `.lkm` 后，`c0data.cls` 由 98 → 88 行，
**其后所有条目的索引都要重算**（本次 `fileRedirection` 有 1 处受影响：`system/22`
由 97 → 87）。改完必须校验：`cls` 与实际文件一致、且 `fileRedirection` 无越界索引。

### 安装包外壳图标的坑

安装包 exe 的"外壳"是 **7-Zip 的 SFX 模块（`7z.sfx`）**，它自带 **7-Zip 图标**——
只把我们的文件塞进去，玩家在资源管理器里看到的仍是 7-Zip 图标。

解决：构建前**先给 SFX 模块替换图标**，得到 `7z_custom.sfx`，再用它拼装。
工具 `setup/patch_pe_icon.py`（用 Win32 `BeginUpdateResource`/`UpdateResource`/`EndUpdateResource`）。

```bash
cp "<7zip安装目录>/7z.sfx" setup/7z_custom.sfx
python setup/patch_pe_icon.py setup/7z_custom.sfx setup/game.ico
```

`build_installer.py` 已指向 `7z_custom.sfx`。

> 校验：`7z.sfx` 的资源区 9,976 字节 → 替换后 190,328 字节；
> 从 exe 提取图标确认已变为我们的图。

## 14. 分号路径自动兼容（2026-09-12）

### 14.1 问题

目录名含分号 `;` 时（Steam 正本就叫 `ROBOTICS;NOTES DaSH`，副本通常还带中文），
补丁装了却完全静默失效：游戏显示原版语言，`languagebarrier/log.txt` 从不生成。

**机制**：Windows 加载器把目录路径**按 `;` 切开**，把分号后面每一段当成
**相对目录名**（相对游戏目录）再搜一遍。本地代理 DLL 只有落在那个子目录里才会被加载。

    RNDt                    → 无片段          → 本地 ✓
    RND;t（无 t\ 子目录）     → 片段 t 不存在   → 系统 ✗
    RND;t（建了 t\ 放 DLL）   → 片段 t 存在     → 本地 ✓
    ROBOTICS;NOTES DaSH     → 片段 NOTES DaSH 已存在 → 本地 ✓

长度和中文都不是变量（早期"中文""长路径"两个结论都是误判，样本混了变量）。

> 顺带解释了 CoZ 原版补丁为什么在 payload 里塞一个 `NOTES DaSH\`：
> 那正是 Steam 正本目录名分号后的片段，是它写死的 workaround。
> 玩家把目录改成副本后片段对不上，补丁就静默不加载了。

### 14.2 实现

- `SemicolonFragments(dir)`：算出目录名里分号后每一段（去掉尾随空格/点 ——
  Win32 建目录时会静默去掉它们，名字对不上就白建）；**实时按 `g_gameDir` 计算**，
  不写死任何名字。
- 安装流程新增 6.5 步：建这些片段子目录，把 8 个代理文件复制进去
  （`dinput8.dll` / `d3d9/d3d10/d3d10_1/d3d10core/d3d11` / `dxgi` / `VSFilter.dll`）。
- 安装流程新增 9 步**自检**：片段子目录里没落到 `dinput8.dll` 就明确弹警告 ——
  这个坑的可怕之处正是"静默"，宁可报一次错也不要让玩家自己去发现。
- `PathLoadNotice(dir)`：界面上一行告知「将自动建 xxx\ 兼容」，**不再阻止安装**
  （旧版 `PathLoadWarning` 的"含分号且长度 > 55 就警告"已删除 —— 长度不是变量）。
- 备份阶段：子目录清单 = 算出来的片段 ∪ 硬编码 `NOTES DaSH`（兼容旧安装），去重。

### 14.3 卸载

`g_fragDirs` 单独一组处理，与 `languagebarrier` / `NOTES DaSH` 区别对待：

- 那些目录名**来自玩家自己的目录名**，里面未必只有我们的东西 → **逐文件**只删
  那 8 个代理名字，目录空了才 `RemoveDirectoryW`，非空保留。绝不整树删。
- 备份里有的（安装前就在该子目录）走**恢复**，不删。

### 14.4 同期修复：重装后卸载残留

对已装过补丁的目录再装一次时，安装器把那里的代理 DLL 也当"既有文件"备份，
卸载器便按「安装前就存在 → 恢复」把它们留了下来（实测残留 8 个文件，
纯净母本并没有）。修法：安装前**比对内容**，与 payload 根目录同名文件
一致的（= 上次装的补丁）不备份。

> 测试：`scripts/diagnostics/test_reinstall_clean.py` 覆盖两个方向 ——
> A) 装两次再卸载必须干净；B) 外来 `dinput8.dll` 必须被还原而非删除
> （防止把 A 的修法改宽成"什么都删"）。

## 15. 三个窗口统一 + 启动器修复 + 卸载器改名（2026-09-12 晚）

### 15.1 真正的"显示有问题"：三个 exe 都没声明 DPI 感知

实测：系统 DPI 120（125%），窗口却报 96 —— Windows 把整个界面位图**拉伸 1.25 倍**。
启动器客户区 1125×775 而逻辑只有 900×620，正好 1.25 倍。后果是**发虚、边缘发糊**。

三个 exe 现在都在建窗口前 `SetProcessDPIAware()`，按真实 DPI 换算客户区尺寸；
绘制用 `Graphics::ScaleTransform` 缩放坐标系，**布局常量保持逻辑值**。

```
建窗口: SetProcessDPIAware() → GetDeviceCaps(LOGPIXELSX) → S = dpi/96
        → 客户区 (int)(WIN_W*S)
绘制  : gr.ScaleTransform(S, S)          → 之后全按逻辑坐标写
命中  : unscale(鼠标坐标) → 逻辑坐标再比
子控件: 原生控件是物理坐标 → 创建 + WM_SIZE 时都要乘 S（安装器的 EDIT）
```

`BltBit` 要用**物理**尺寸（`pw/ph`），不能用被换算过的逻辑值 —— 否则只拷左上角一块，
主按钮整片消失（自己踩过）。

### 15.2 启动器「开始游戏」被切

旧 `StartRect() = X660 + 宽250 → 右边界 910`，而 `WIN_W = 900`。手写死坐标超出窗口。
修法：取消所有死坐标，由统一栅格反推（`RW = WIN_W - 32`，按钮右下角对齐）。
窗口 900×620 → 820×580。

**顺带修的 z 序 bug**：下拉列表原先紧接着自己的标题绘制，会被随后绘制的
「影片字幕」与「开始游戏」盖住。现在下拉统一放到 `Paint` 末尾。

### 15.3 卸载器改名 + 专用图标

| | 改前 | 改后 |
|---|---|---|
| 产品名 | `RNDZhUninstall.exe` | `卸载汉化.exe` |
| 图标 | 与启动器共用游戏封面图 | 红底垃圾桶（`uninstall.ico`）——**已作废**，见下 |
| 配色 | 深色霓虹 | 纯白极简（与安装器同一套常量） |
| 主按钮 | 蓝色 | 红色（破坏性操作） |

理由：两个 exe 名字太像又并排躺在游戏目录里，点错的代价是**把汉化卸了**。
图标由 `scripts/make_uninstall_icon.py` 生成（PIL，七档尺寸，4 倍超采样）。

> **中文名不能写在 .bat 里。** cmd 按 OEM 代码页逐行读批处理，`chcp 65001` 只对
> "还没读到的行"生效，编辑器写成 LF 换行也会失效（两种都踩过）。
> 做法：bat 编译成 ASCII 名 → `build/rename_uninstall.py` 改名。

**升级路径**：安装器现在会清 `RNDZhUninstall.exe` / `RNDZh-Uninstall.exe`，
否则老玩家升级后目录里会同时躺着新旧两个卸载器。

### 15.4 截图工具的坑

**窗口矩形 / 客户区 / 客户区偏移** 三个值再换算；只看图像高度会算错一个标题栏（38 px）。
