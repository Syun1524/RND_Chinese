# 版本兼容性（日文版 / 英文版）

> 结论：**同一份补丁同时适用于日文原版与英文原版，无需两套重定向表。** 已实测。

---

## 1. 实测依据

对比 `-原版日语 副本` 与 `-原版英文 副本`（均为干净原版）：

### 1.1 `Game.exe` —— 完全相同

| 文件 | 日版 | 英版 |
|---|---|---|
| `Game.exe` | 相同 | 相同 |
| `launcher.exe` / `launcher.dat` / `facial.bin` | 相同 | 相同 |
| `mes00.cpk` / `mes01.cpk` / `script.cpk` / `model.cpk` / `motion.cpk` / `voice.cpk` | 相同 | 相同 |
| **`bg.cpk` / `manual.cpk` / `movie.cpk` / `system.cpk`** | **不同** | **不同** |

→ **sigScan 特征码两版通吃**（同一个 exe）。

### 1.2 归档内文件顺序 —— 逐条一致

用 GARbro 列出英版归档，与日版解包日志逐条比对（**忽略 `_en`/`_jp` 语言后缀**）：

| 归档 | 日版条目 | 英版条目 | 顺序差异 |
|---|---|---|---|
| `bg.cpk` | 433 | 433 | **0** |
| `system.cpk` | 37 | 37 | **0** |
| `manual.cpk` | 2 | 2 | **0** |

> 例：`bg.cpk` 第 231 项日版叫 `rnd_ibg037a.png`、英版同名；`system.cpk` 第 7 项日版 `data01.png`、英版 `data01_en.png`——**位置相同，只是文件名带语言后缀**。

**因此 `fileRedirection` 的 fileId 在日/英两版指向同一位置的文件 → 同一套重定向表通用。**

---

## 2. 为什么 CPK 体积不同却顺序一致

`bg.cpk`：日版 899,692,032 vs 英版 890,766,848（差约 9MB）。
差异来自**图片内容本身的压缩后大小**（各语言版本的图是分别重绘/压缩的），
**不是文件数量或排列变化**——列表比对已证明条目数与顺序完全一致。

补丁自带重绘后的中文图（在 `c0data/`），**不依赖原版那 4 个 CPK 里的图**，故内容差异无影响。

---

## 3. 唯一会变的东西：原版图片本身

补丁用 `fileRedirection` 把游戏对原图的请求改指到 `c0data/` 的中文图。
**被替换的是"指向"，原版图不参与显示**，所以：

- 日版玩家：原版日文图被中文图替换 ✅
- 英版玩家：原版英文图被中文图替换 ✅

---

## 4. 唯一要注意的差异：`boot.bat`

| | 内容 |
|---|---|
| 日版原版 `boot.bat` | `start launcher.exe JP` |
| 英版原版 `boot.bat` | `start launcher.exe EN` |

补丁**会覆盖 `boot.bat`**（改为触发 LanguageBarrier 劫持）。覆盖后两版行为一致，
所以**不需要区分**。（补丁包内的 `boot.bat` 用哪个原版的都行，因为内容会被替换成劫持逻辑。）

> 注：包内当前 `boot.bat` 内容为 `start launcher.exe JP`，与 CoZ 英文包不同——
> 这是 CoZ 为触发劫持而统一的内容，与"语言"无关。

---

## 5. Steam 依赖

**补丁不依赖 Steam。** 依据：

- 加载方式是 `dinput8.dll` 劫持（游戏因 DRM 已解包，不会重复校验）
- 源码中**无任何 Steam API 调用**
- CoZ 启动器内也**无 `SteamAPI_Init`**，仅有一句显示名和内部路径

→ 自研启动器**直接 `CreateProcess` 拉起 `Game.exe`** 即可；正版、非 Steam 渠道版本均可运行。

---

## 6. 安装器需要做的版本判断（可简化）

由于 fileId 通用，安装器**不需要**为不同版本准备不同重定向表。但仍建议：

1. **校验 `Game.exe` 哈希/SigScan 兼容性**（避免不支持的版本硬装）
2. 记录玩家是日版还是英版（仅用于日志/诊断，不影响安装结果）
3. 若发现**既非日版也非英版**（如未来 Steam 更新改动结构），**停止安装**并提示
