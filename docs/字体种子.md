# 字体种子（预烘焙字形缓存）

## 这是什么

补丁包里 `languagebarrier/fonts/` 下的 `fontData.bin` + `font_NN.dds` / `outline_NN.dds`
是**预先烘焙好的中文字形图集**（12 档字号），让玩家首次进各界面时不必等待烘焙。

游戏的字形是**惰性烘焙**的：`TextRendering::getFont(size)` 发现该字号没烘过就当场
用 FreeType 把 charset 里全部字形（当前 4434 个）光栅化 + 描边，再 `SaveToDDSFile`
落盘。这个动作**同步阻塞主线程**，单档约 0.5~2 秒（字号越大越慢）。

## 为什么需要预置

1. **省掉玩家的卡顿**。不预置的话，玩家要卡若干次（每撞到一个新字号卡一次）。
2. **绕开写盘权限问题**（更关键）。`Game.exe` 的 manifest 是 `asInvoker`（不提权），
   而 Steam 默认装在 `Program Files (x86)`。游戏运行时要往自己目录写几十 MB 图集，
   在权限受限时会失败 —— 那样**每次启动都要重烘一遍**，不是"卡五次"。
   预烘焙让这些文件由**提权的安装器**放进去，游戏只需读取。

## 怎么重烘

字号**不在脚本里**，由引擎运行时填的 `glyphDisplayHeight × 1.5` 决定，**只能实测跑出来**。

1. 准备一个已装补丁的游戏目录（**清空** `languagebarrier/fonts/` 下的
   `fontData.bin` 与 `*.dds`，只留 `.otf`）。
2. 启动游戏，**把各类界面都走一遍**：主线对话、历史记录 backlog、TIPS、
   带注音的段落、系统菜单、存档/读档、Twipo/手机、报告界面。
   撞到未烘字号时会卡一下 —— **卡顿本身就是进度信号**。
3. **正常退出游戏**（走游戏内菜单）。缓存是在 `closeAllSystemsHook` 里写盘的，
   强杀或崩溃会让这一轮白做。
4. 把 `languagebarrier/fonts/` 下的 `fontData.bin` 与全部 `*.dds` 收进补丁包。

已知档位（2026-09-25 在日文版跑出，12 档）：
`18 / 25 / 27 / 28 / 30 / 32 / 34 / 37 / 40 / 42 / 43 / 45`

其中三档来自 `patchdef.json` 的配置项（注意**前两个乘了 1.5**）：

| 配置项 | 配置值 | 实际字号 | 用途 |
|---|---|---|---|
| `dialogueFontSize` | 28 | **42** | 对话正文 |
| `backlogFontSize` | 27 | **40** | 历史记录 |
| `tipReimplementationGlyphSize` | 32 | **32**（不乘） | TIPS / 名词解释 |

⚠️ **没法保证烘全**。字号由游戏脚本运行时决定，不同玩法路径会撞到不同字号
（实测日文版跑出 12 档、英文版跑出 8 档，并集 14 档）。已知缺口举例：
`GameText.cpp` 里硬编码 `getFont(64)`（报告界面），**64 不在 12 档内**，
首次打开报告界面仍会当场烘一次。未预置的字号不会出错，只是当场烘一下。

## 校验

改动 charset 或重烘之后，跑工作区的门禁：

```bash
python scripts/check_seed_fonts.py -v
```

它比对 `fontData.bin` 里每档存的 `charsetHash` 与当前 `patchdef.json` 的 charset 是否同代。
**这个校验必须做**：charset 一改，hash 就变，运行时会判定
「Font cache was baked from a different charset」并**把整份种子丢弃重烘** ——
玩家又回到卡顿，而游戏不报错、常规验收也查不出来（属于静默失效）。

指纹算法（`TextRendering.cpp` 的 `Init()`）：

```
charsetHash = FNV-1a(charset) 再折叠 narrowQuotes / quoteWidth32 / quoteInset32
```

⚠️ **只算 charset 是错的** —— 那三个字形度量参数会改变烘焙出的 advance，
必须进同一个指纹。当前期望值：**`0xbb9e4db4`**（charset 4550 字符，
度量 `narrowQuotes=true / quoteWidth32=16 / quoteInset32=3`）。

## JP / EN 共用一份种子

种子的 `lang` 字节（JP=0 / EN=1）来自 `boot.bat` 的语言 token。
CoZ 上游的 `loadCache()` 会校验它，不符就丢弃整份缓存。

但**我们 `forceIncludeHan=true`**，中文码表在两种语言下都烘全部汉字 ——
实测 JP 缓存与 EN 缓存**逐字形对比 `glyphMap`/`outlineMap` 完全相同、图集 md5 也相同**，
唯一差别就是那个 `lang` 字节。所以那份校验对本补丁只剩副作用
（把一份本来能用的缓存丢掉）。

已改为**跟随 `forceIncludeHan`**（`TextRendering.cpp` 的 `loadCache()`）：
开启时跳过该校验，一份种子同时服务日文版与英文版玩家；
将来若关掉该配置（例如做纯日文补丁），校验自动恢复，不会静默画出乱码。

实机验证见工作区 `scripts/diagnostics/verify_lang_cache_shared.py`（四段，含反向对照）。

## 体积

12 档原始 **211.7 MB**，进安装包压缩后约 **+31 MB**（A8 图集压缩率约 5.6:1）。
